## 1. 背景与问题

管理员当前可以进入“记账”页面，但页面只有空的骨架，无法统一查看线上收款、维护线下收款和支出，也无法根据时间范围查看收入、支出、利润和全站剩余额度等关键数据。

## 2. 目标

1. 将`/accounting`完善为管理员使用的全宽记账页面。
2. 提供线上收入、线下收入、支出、统计分析四个 Tab，其中统计分析本期只保留空状态或占位区域。
3. 对接线上支付成功订单，支持人工维护线下收入和支出。
4. 提供时间筛选，并让统计卡片与表格遵循同一筛选范围；全站剩余额度不受时间筛选影响。
5. 通过后端数据模型与 API 持久化线下账单，并在服务端完成用户存在性校验、权限校验和数据汇总。

## 3. 非目标

- 本期不实现“统计分析”Tab的图表、趋势、排行等具体分析内容。
- 本期不引入汇率换算；净利润按用户指定规则直接进行数值相减。
- 不改变既有`/billing-records`页面的账单类型和付款方式定义；记账页面应复用其既有业务枚举或等价后端定义。

## 4. 用户与权限

- **用户角色**：管理员。
- **前置条件**：用户具有现有路由要求的管理员角色。
- **权限原则（已确认方案的必要组成）**：新增的线下收入、支出写入和删除操作必须由服务端再次校验管理员权限，不能只依赖前端路由守卫。

## 5. 已确认的功能需求

### 5.1 页面布局

- 页面默认全宽。
- 顶部为统计卡片栏，视觉风格参考`/wallet`顶部统计栏。
- 统计栏下方为工具栏：左侧 Tab，右侧为“添加账单”和“筛选”。
- “添加账单”仅在线下收入、支出 Tab显示。
- 工具栏下方为当前 Tab的表格主体。

### 5.2 统计卡片

统计项目及规则：

| 项目 | 单位 | 计算规则 | 时间筛选 |
| --- | --- | --- | --- |
| 总收入 | ¥ | 线上收入 + 线下收入 | 受影响 |
| 线上收入 | ¥ | 筛选范围内线上支付成功订单金额合计 | 受影响 |
| 线下收入 | ¥ | 筛选范围内线下收入金额合计 | 受影响 |
| 总支出 | ¥ | 筛选范围内支出金额合计 | 受影响 |
| 毛利润 | ¥ | 总收入 - 总支出 | 受影响 |
| 净利润 | ¥ | 毛利润 - 全站剩余额度 | 仅“全部”可计算 |
| 全站剩余额度 | $ | 从用户页面现有“全站剩余额度”接口取得 | 不受影响 |

- 净利润的负数格式必须为`¥-50`，不能为`-¥50`。
- 当时间范围不是“全部”时，净利润显示短横线`-`。
- 本期不考虑人民币与美元汇率，净利润直接使用数值相减。

### 5.3 Tab与操作

Tab固定为：

1. 线上收入
2. 线下收入
3. 支出
4. 统计分析

右侧操作：

- “添加账单”：仅在线下收入、支出显示；用于新增当前 Tab对应的人工账单。
- “筛选”：打开筛选弹窗。

### 5.4 线上收入表

- 数据来源：所有用户支付成功的线上收款订单。
- 表头：账单单号、消费类型、付款方式、实际支付、用户、创建时间。
- 用户单元格显示两行：第一行用户名称，第二行用户 ID。
- 支持分页。
- 消费类型、付款方式应与`/billing-records`页面已有定义保持一致。

### 5.5 线下收入表

- 数据来源：管理员人工维护的线下收款账单。
- 表头：付款方式、实际收入、用户、创建时间、操作。
- 用户单元格显示两行：第一行用户名称，第二行用户 ID。
- 支持分页。
- 操作栏包含编辑和删除图标按钮。
- 新增/编辑表单字段：付款方式、实际支付、用户 ID、创建时间。
- 创建时间默认当前时间。
- 提交时服务端必须根据用户 ID查询用户是否存在；不存在时不得保存。
- 保存成功后列表中的用户列显示用户名称和用户 ID。

### 5.6 支出表

- 数据来源：管理员人工维护的支出账单。
- 表头：支出目标、付款方式、实际支出、创建时间、操作。
- 支持分页。
- 操作栏包含编辑和删除图标按钮。
- 新增/编辑表单字段：支出目标、付款方式、实际支出、创建时间。
- 支出目标允许任意文本填写。
- 创建时间默认当前时间。

### 5.7 筛选弹窗

筛选按钮行为参考`/dashboard/models`的筛选按钮，但本页面不需要“仅限管理员”项。

- 快速范围：全部、1天、1周、1月。
- 支持自定义开始时间、结束时间。
- 图表设置中的时间粒度：天、周、月；本期仅保存/传递该条件，不实现统计分析图表。
- 应用筛选后，表格查询和统计卡片使用同一时间范围。
- 全站剩余额度不受时间范围影响。

## 6. 数据与外部约束（已确认/待确认分开）

### 6.1 已确认

- 采用完整后端方案：新增人工账单数据持久化、增删改查 API、线上收入查询/汇总 API，以及服务端用户校验。
- 线上收入复用现有 `/billing-records` 消费记录口径：统计所有用户状态为成功的充值（`topup`）和订阅购买（`subscription`）订单，排除管理员手动充值以及钱包余额内部抵扣。
- 付款方式和消费类型复用 `/billing-records` 页面及其后端定义中的既有选项；本期不额外创建可自由维护的付款方式字典。
- 快速时间范围采用滚动时间：1天=最近 24 小时、1周=最近 7 天、1月=最近 30 天；全部不设置时间边界，并保留自定义开始时间和结束时间。
- 人工账单金额必须大于 0、最多两位小数，单笔上限为 `¥999,999,999.99`；不允许使用 0 或负数冲销。
- 人工账单删除采用硬删除，前端需要二次确认，后端执行实际删除。
- 统计卡片由独立的后端统计汇总接口返回；列表接口只负责分页数据。
- “全部”表示不传开始/结束时间，默认加载全部历史数据。
- 页面首次进入时默认打开“线上收入”Tab。
- 页面首次进入时默认使用“全部”时间范围。
- 需要兼容项目支持的 SQLite、MySQL、PostgreSQL。
- 前端应复用现有页面布局、统计卡片、Dialog、表格、分页、筛选和 i18n 能力。

### 6.2 待确认

- 无。

## 7. 验收标准

1. 管理员打开`/accounting`时，页面为全宽布局，顶部显示七项统计卡片。
2. 统计卡片按已确认公式计算，人民币负数格式为`¥-数值`；非“全部”筛选下净利润显示`-`。
3. 四个 Tab按要求显示；统计分析暂不展示具体图表。
4. 线上收入仅展示支付成功订单，字段、用户双行展示、分页和时间筛选可用。
5. 线下收入和支出均可新增、编辑、删除；表单默认当前时间，非法用户 ID无法保存。
6. 添加账单按钮只在目标两个 Tab显示，筛选弹窗包含指定快速范围和时间粒度且无管理员限定项。
7. 刷新页面后人工账单仍存在；非管理员不能通过直接调用接口完成写入、修改或删除。
8. 既有账单记录页面、钱包页面和用户页面的行为不被破坏。
