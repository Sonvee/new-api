# 个人资料页身份铭牌 PRD

## 文档元信息

- 状态：已实现，待开发者手动验证
- 关联计划：`docs/plans/03-profile-identity-badge-plan.md`
- 最后确认范围：2026-09-16
- 当前已确认：在 `/profile` 个人资料页为 `vip`、`svip`、`premium` 三个用户分组提供专属身份铭牌；封装为接收用户身份字符串的公共组件；其他分组保持原始展示，不应用专属铭牌样式

## 1. 背景与问题

个人资料页当前在用户基础信息区域以普通文本展示 `profile.group`，无法突出高等级用户身份。需要增加一个可复用的身份铭牌组件，为指定尊贵分组提供明显且有层级差异的视觉表达，同时不改变其他分组的既有展示。

## 2. 目标与非目标

### 2.1 目标

- 封装公共身份铭牌组件，核心输入为用户身份/分组字符串。
- 仅对 `vip`、`svip`、`premium` 提供专属样式。
- `default` 及其他未支持分组保持现有原始文本展示，不套用专属铭牌样式。
- 在亮色与暗色主题下保持文字可读、边界清晰，并兼顾减少动态效果的系统偏好。

### 2.2 非目标

- 不修改后端用户分组、权限、计费或订阅逻辑。
- 不修改分组名称或增加新的分组类型。
- 不将专属铭牌样式自动扩散到用户列表、日志、定价、渠道等现有 `GroupBadge` 使用场景，除非后续明确扩大范围。
- 不新增第三方视觉或动画依赖。

## 3. 用户与场景

- 使用者：访问个人资料页的已登录用户。
- 数据来源：个人资料接口返回的 `profile.group` 字符串。
- 当前页面位置：`web/src/features/profile/components/profile-header.tsx` 的用户名、邮箱、用户组基础信息区域。

## 4. 功能需求

### FR-1 公共组件输入与输出

- 公共组件接收用户身份/分组字符串，并负责判断是否属于专属身份。
- 身份匹配忽略大小写，例如 `VIP`、`Vip`、`vip` 均匹配 VIP 样式；展示文本保留调用方传入的原始内容。
- 输入为 `vip`、`svip` 或 `premium` 时，渲染对应专属铭牌。
- 输入为 `default`、空值或其他分组时，不应用三种专属样式，保持调用位置的原始展示语义。
- 专属铭牌内的身份文字自动大写；普通身份不改变输入文本内容。

### FR-2 VIP 铭牌

- 使用淡蓝色边框。
- 使用比边框更浅、半透明的蓝色背景填充。
- 无动态效果。

### FR-3 SVIP 铭牌

- 使用玫瑰红色边框。
- 使用更浅、半透明的玫瑰红色背景填充。
- 整体具有荧光效果。
- 不要求流动动画。

### FR-4 Premium 铭牌

- 使用流动的白金色边框。
- 使用黑曜石质感的深色背景填充。
- 铭牌文字使用彩色流光效果并带文字光晕。
- 整体带彩色荧光效果。
- 在用户启用 `prefers-reduced-motion: reduce` 时停用流动动画，保留静态高级质感和可读性。

## 5. 交互与状态

- 铭牌为纯展示组件，不可点击，不引入悬停操作或额外交互。
- 身份文本保持单行，避免在紧凑的个人资料头部换行破坏布局。
- 对不支持的身份不制造新的视觉层级。
- 在当前 `用户名 · 邮箱 · 用户组` 信息行中，用公共组件替换现有用户组文本的渲染位置。
- `vip`、`svip`、`premium` 在该位置显示专属铭牌；`default`、空值和其他分组继续保持普通文本展示。

## 6. 数据与外部约束

- 前端技术栈为 React 19、TypeScript、Tailwind CSS 4，并已有 `Badge`、`StatusBadge`、`GroupBadge` 等组件。
- 现有 `GroupBadge` 会为一般分组生成自动颜色，直接用于本需求会改变“其他身份原样展示”的行为；本次需优先评估新增聚焦身份展示的公共业务组件，而不是修改其所有既有调用点。
- 视觉实现优先使用现有 Tailwind/CSS 能力和项目主题约定，不新增依赖。
- 动画仅用于 `premium` 的流光表达，并必须提供 reduced-motion 降级。

## 7. 验收标准

1. 公共组件能够根据传入身份区分 `vip`、`svip`、`premium` 与其他值，并将三种专属铭牌内的文字自动大写。
2. `vip` 显示淡蓝边框和浅蓝半透明背景，且没有动画。
3. `svip` 显示玫瑰红边框、浅玫瑰红半透明背景和可见但不过度影响阅读的荧光效果。
4. `premium` 显示流动白金边框、黑曜石背景、彩色流光文字、文字光晕和彩色整体荧光。
5. reduced-motion 模式下不播放流动动画，身份文字仍清晰可读。
6. `default`、空值和其他未支持分组不应用专属铭牌样式，保持确认后的原始展示方式。
7. 个人资料头部在移动端与桌面端均不因铭牌产生横向溢出或遮挡姓名、角色、用户 ID。
8. 不新增第三方依赖，不修改后端、数据结构和其他页面的分组展示行为。
