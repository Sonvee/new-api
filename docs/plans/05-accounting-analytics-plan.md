## 1. 已确认范围

本计划只覆盖统计分析 Tab，不重新设计或重构已经实施的线上收入、线下收入、支出、统计卡片和人工账单 CRUD。

已确认的产品行为：

- 展示一个财务趋势图表，参考 `/dashboard/models` 的“消耗分布”图表。
- 系列固定为：总收入、总支出、毛利润。
- X 轴为时间，Y 轴为人民币金额。
- 支持并列柱状图和非堆叠面积图切换；柱状图不得设置堆叠。
- 默认显示柱状图，不保存上次图表类型。
- 复用页面当前时间范围和按天/按周/按月粒度；切换图表类型不重置筛选。
- 在筛选范围内补齐连续时间点，缺失指标按 0 展示。
- 长时间范围不自动切换粒度、不截断数据；图表内容超出可读宽度时允许横向查看。
- 图例支持显示/隐藏任意系列，初始三个系列全部显示。
- 使用现有记账金额格式：`¥`、两位小数、负数形如 `¥-50.00`。
- 无数据时保留图表容器并采用现有图表空数据表现。

## 2. 总体实现思路

新增一个记账趋势数据接口，单独返回已经按时间粒度聚合的三个财务系列；不要让前端分别拉取分页列表后自行重算历史趋势。前端在统计分析 Tab 挂载趋势查询，使用当前页面筛选条件和粒度构造查询参数，然后将响应转换为 VChart 所需的数据行。

图表组件沿用现有 `ConsumptionDistributionChart` 的结构：

1. 标题区左侧显示统计分析标题和必要的时间范围/汇总信息；
2. 右侧使用相同的柱状图/面积图切换交互；
3. 图表区使用项目已有 `VChart`、主题同步、`VCHART_OPTION` 和响应式容器；
4. 柱状图设置 `stack: false`，通过 `xField: [Time, Metric]` 二级 band 和 `seriesField` 形成同一时间点的并列 Bar；
5. 面积图设置 `stack: false`，保留现有面积透明度、平滑折线和图例交互；
6. 长数据集使用 VChart 内置水平 scrollBar（filterMode: axis）查看完整时间域；根据可用宽度设置可读窗口，不裁切数据数组、不改变粒度，也不创建超大 canvas。

## 3. 后端技术设计

### 3.1 API 契约

新增管理员接口：

- **方法**：`GET`
- **路径**：`/api/accounting/trend`
- **权限**：沿用 accounting 路由组的 `middleware.AdminAuth()`
- **查询参数**：`start_time`、`end_time`、`granularity`
- **granularity**：`day`、`week`、`month`

已实施响应结构：

`data` 返回：

- `granularity`
- `items`：按时间升序排列的时间点数组
- 每项包含：`time`、`total_income_cents`、`total_expense_cents`、`gross_profit_cents`

接口必须保证：

- 与现有 `GetAccountingStats` 使用完全相同的线上收入过滤口径：仅成功充值/订阅，排除管理员补单和余额购买；
- 线下收入和支出来自 `accounting_entries`；
- 每个时间桶先分别累加线上收入、线下收入和支出，再计算总收入与毛利润，不能将各时间桶的派生值从不一致的数据源计算；
- 时间桶使用服务端 `time.Local`（与现有公开用量日期接口一致）：日为当地零点，周从周一零点开始，月为每月一日零点；记录筛选仍使用 Unix 秒的闭区间。`time` 返回桶开始日期字符串 `YYYY-MM-DD`，前端直接展示，不按浏览器时区二次转换；
- 当筛选范围为空或没有任何账单时，返回空数组，不伪造业务数据；
- 当筛选范围内存在账单时，补齐范围内连续时间桶，缺失值为 0；“全部”没有显式边界时，使用有效账单的最早和最晚时间作为补齐边界；首尾不完整桶仅统计实际筛选范围内的记录；
- 对 `granularity` 做服务端白名单校验，非法值返回明确 4xx；
- 保持 SQLite、MySQL、PostgreSQL 兼容，避免依赖单一数据库的日期截断函数；必要时查询原始时间和金额后在 Go 中按统一时区聚合。

### 3.2 后端文件边界

计划修改：

- `model/accounting.go`：将两类线上收入查询提取为共享业务口径，供列表、汇总和趋势共用。
- 新增 `model/accounting_trend.go`：趋势 DTO、粒度校验、时间桶聚合和连续桶补齐逻辑；通过 GORM Rows 流式读取时间与金额，避免全量订单驻留内存。
- `controller/accounting.go`：解析时间筛选和粒度，调用模型层并返回统一 API 响应。
- `router/api-router.go`：在既有管理员 accounting 路由组注册 `GET /trend`。

不修改：

- 既有账单列表接口和统计卡片接口的公开契约；
- 充值、订阅、钱包流水、用户模型及日志数据库结构；
- `relaykit/`。

## 4. 前端技术设计

### 4.1 数据与状态

- 在 `web/src/features/accounting/api.ts` 新增 `getAccountingTrend`。
- 在 `web/src/features/accounting/types.ts` 新增趋势响应、时间桶和图表类型类型。
- 新增 `web/src/features/accounting/lib/charts.ts` 承载记账趋势 spec 转换，与展示组件分离，避免图表组件混入大量配置逻辑。
- 在 `web/src/features/accounting/constants.ts` 新增图表类型选项，复用现有 `Bar Chart`、`Area Chart` 文案键和默认柱状图约定；如复用 dashboard 常量会造成 feature 耦合，则在 accounting feature 内定义同值配置。
- 在 `web/src/features/accounting/index.tsx` 仅在 `activeTab === 'analytics'` 时发起趋势查询，避免其他 Tab 请求无用途的图表数据；将 `filters.granularity` 和 `timeQuery` 传给图表组件。
- 查询 key 必须包含时间范围和粒度；筛选应用或重置后由参数变化触发重新请求。

### 4.2 组件与图表转换

新增 `web/src/features/accounting/components/accounting-trend-chart.tsx`，职责限定为：

- 图表容器、标题、图表类型切换；
- VChart 主题和生命周期处理；
- 将 API 时间桶转换成 VChart 的长表结构；
- 配置金额轴、图例、Tooltip、空数据和横向滚动；
- 不在组件中重复实现后端聚合或页面筛选逻辑。

必要时在 `web/src/features/accounting/lib/format.ts` 增加图表金额格式化函数，确保轴标签和 Tooltip 使用 `¥` 两位小数，并正确处理负数符号位置。

VChart 配置要求：

- 并列柱状图：`type: 'bar'`、X 为时间、Y 为金额、`seriesField` 为指标名称、`stack: false`；
- 非堆叠面积图：`type: 'area'`、相同 X/Y/series 字段、`stack: false`；
- 三个系列使用稳定的语义色，图例可交互；不要仅依赖颜色传达指标含义；
- Tooltip 在同一时间点展示三个指标及格式化金额；
- 数据为空时使用现有图表空数据 spec，不把整个 Tab 替换成页面级 `EmptyState`；
- 当前主题变化时刷新 VChart 主题；保留深色模式和主题定制兼容性；
- 遵循无障碍要求，为图表切换按钮提供可见文本和可访问状态，不新增仅图标操作。

### 4.3 页面集成

将 `web/src/features/accounting/index.tsx` 中统计分析分支的现有空状态替换为趋势图表组件。统计分析仍保留页面顶部统计卡片、筛选按钮和当前筛选状态；不要为图表另建一套筛选弹窗。

趋势图表容器使用 `h-full min-h-0` 与纵向 Flex 布局填充统计卡片、工具栏之外的全部剩余高度，不设置固定像素高度；窄屏下通过图表内置水平滚动条允许横向查看，同时页面本身不产生无意义的横向滚动。图表切换按钮保持与 dashboard 图表一致的视觉和键盘交互。

### 7.2 开发者手动验证清单

#### API 与数据口径

- 管理员可按天、周、月和自定义时间范围查询趋势；非管理员无法访问。
- 成功充值、成功订阅计入；失败/待支付、管理员补单、余额订阅不计入。
- 线上收入、线下收入、总支出、总收入和毛利润在每个时间桶内计算正确。
- 时间桶连续，空桶和缺失指标为 0；开始/结束边界正确。
- 非法粒度、非法时间范围返回明确 4xx；空数据返回合法空数组。
- SQLite、MySQL、PostgreSQL 均完成真实实例验证，且迁移/重启不产生回归。

#### 前端图表

- 统计分析 Tab 只请求一次有效趋势数据，其他 Tab 不发送趋势请求。
- 默认柱状图为并列 Bar，不是堆叠 Bar；面积图为非堆叠。
- 柱状图和面积图切换保留筛选和粒度。
- 图例可以显示/隐藏三个系列；Tooltip 和 Y 轴金额使用 `¥` 两位小数，负数为 `¥-...`。
- 长时间范围不自动改粒度、不截断历史数据，窄屏可横向查看。
- 空数据、加载、错误、深色主题、键盘操作和七种语言显示正常。

## 8. 迁移、发布、回滚与风险

- 现有消耗分布组件绑定模型、quota 和站点币种，不能直接用于人民币财务数据；保留该组件行为，新增 accounting feature 图表以组合既有 Button、IconBadge、LoadingState、ErrorState 和 VChart。
- 本功能只新增趋势查询接口和前端图表，不新增数据库表、字段或迁移。
- 后端聚合若在 Go 中读取原始订单，需关注历史数据量；实现时应优先使用可分页/可控范围的查询方式，避免无界内存增长。
- 如果现有订单金额为浮点数，统一沿用记账统计边界的“转换为分”规则，不引入新的舍入口径。
- 图表数据量可能在“全部 + 按天”时较大；按计划使用横向查看，但仍需由实现者确认 VChart 对长序列的稳定性。
- 回滚只需恢复前端占位和移除趋势路由/查询代码，不涉及数据库回滚。
- 不引入第三方依赖，不修改 `relaykit/`、公开账单行为或项目受保护身份信息。
