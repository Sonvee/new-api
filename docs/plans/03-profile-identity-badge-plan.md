# 个人资料页身份铭牌开发计划

## 文档元信息

- 状态：已实现，待开发者手动验证
- 对应 PRD：[`docs/prd/03-profile-identity-badge.md`](../prd/03-profile-identity-badge.md)
- 计划范围确认日期：2026-09-16
- 实施边界：仅新增公共身份铭牌组件及其必要样式，并在个人资料头部替换现有用户组文本渲染；不修改后端、数据结构、分组业务、其他页面或现有全局 `GroupBadge` 行为。
- 验证边界：AI 不编写测试脚本，不执行测试、类型检查、Lint、构建或其他自动化验证；仅向开发者提供手动验证建议。

## 1. 总体实现方案

1. 在公共组件目录新增 `IdentityBadge`，以用户身份字符串作为核心输入，并允许透传必要的 `className` 以适配公共调用场景。
2. 组件内部对去除首尾空白后的身份执行不区分大小写匹配；专属铭牌内的身份文字统一转换为大写，普通身份继续展示原始文本。
3. 未支持身份直接渲染普通文本容器，不套用 `Badge`、自动颜色、边框、背景或光效；空值不渲染内容，以保持个人资料页当前条件展示行为。
4. 专属身份复用项目现有 `Badge` 基础组件的尺寸、语义和基础布局，通过明确的身份样式扩展实现三种视觉层级。
5. `vip` 与 `svip` 使用 Tailwind 工具类完成静态颜色、透明背景及光晕；`premium` 使用局部 CSS 类和伪元素实现白金流动边框、黑曜石背景、彩色流光文字及整体彩色荧光。
6. 在 `prefers-reduced-motion: reduce` 下关闭 `premium` 边框和文字的动画，只保留静态渐变、背景与光晕。
7. 在 `ProfileHeader` 当前用户组文本位置接入 `IdentityBadge`，保持用户名、邮箱、分隔符、角色徽章和用户 ID 徽章的现有布局与行为。

## 2. 现有能力复用与能力缺口

### 2.1 复用

- 复用 `web/src/components/ui/badge.tsx`：专属身份仍使用项目统一徽章高度、圆角、字体和单行布局。
- 复用 `web/src/lib/utils.ts` 的 `cn()`：合并身份样式与调用方类名。
- 复用 `web/src/styles/index.css` 已采用的 CSS 自定义属性、`@property`、渐变遮罩、关键帧及 reduced-motion 组织方式。
- 保留 `ProfileHeader` 当前响应式 Flex 布局和用户组的原始数据来源 `profile.group`。

### 2.2 不直接复用或修改的候选

- `GroupBadge` 不适合直接用于本需求：它会为普通分组生成自动颜色并默认继承 `StatusBadge` 的复制行为，无法满足“其他身份保持普通原文”的契约；修改它还会影响用户列表、日志、定价、渠道、订阅等大量既有调用点。
- `StatusBadge` 不适合承载全部效果：其颜色模型基于固定状态色和自动颜色，不包含白金流动边框、黑曜石背景和彩色流光文字；为本需求扩展其公共 variant 会扩大无关组件 API。
- 不引入 `motion`、GSAP 或其他动画依赖：本需求仅需 CSS 循环渐变，使用现有 CSS 能力更轻量，且 reduced-motion 降级更直接。

## 3. 目标文件与职责

### 3.1 公共组件

- `web/src/components/identity-badge.tsx`（新增）
  - 定义 `IdentityBadgeProps`，核心字段为 `identity?: string | null`，可选接受 `className`。
  - 归一化身份用于匹配；专属铭牌文字展示为大写，普通身份不修改最终展示文本。
  - 未支持身份渲染普通文本；空值返回 `null`。
  - `vip`、`svip`、`premium` 使用明确的分支映射，不建立超出当前三种身份的配置系统。
  - 使用非交互语义，不添加按钮、点击、复制、Tooltip 或 ARIA 交互状态。
  - 不额外指定圆角，沿用基础 `Badge` 的主题圆角。

### 3.2 全局样式

- `web/src/styles/index.css`
  - 在现有动画样式区域附近新增身份铭牌的局部命名 CSS 类、自定义角度属性和关键帧。
  - Premium 外层伪元素绘制流动白金边框，内层保持黑曜石深色背景。
  - Premium 文本通过背景渐变裁切形成彩色流光，并用 `text-shadow` 提供文字光晕。
  - Premium 整体使用克制的多色 `box-shadow`，避免光效遮盖相邻文本。
  - reduced-motion 媒体查询将动画设为 `none`，并固定为可读的静态渐变位置。
  - VIP 不定义动画；SVIP 只使用静态光晕。

### 3.3 个人资料页接入

- `web/src/features/profile/components/profile-header.tsx`
  - 导入公共 `IdentityBadge`。
  - 将当前 `<span className='truncate'>{profile.group}</span>` 替换为组件调用。
  - 保留现有 `profile.group` 条件、前置分隔符和信息行结构。
  - 为组件传入与当前文本一致的截断/收缩约束，确保移动端不产生横向溢出。

### 3.4 测试与验证边界

- 不新增或修改测试文件。
- 不执行测试、类型检查、Lint、格式检查或构建。
- 开发完成后向开发者提供手动验证清单，覆盖三种特殊身份、普通身份、大小写匹配、亮暗主题、移动端布局和 reduced-motion 降级。

## 4. 视觉规格

### 4.1 VIP

- 边框：淡蓝色，亮暗主题均保持可辨识。
- 背景：更浅的蓝色半透明填充。
- 文字：清晰蓝色系，满足小字号可读性。
- 动态：无。

### 4.2 SVIP

- 边框：玫瑰红色。
- 背景：浅玫瑰红半透明填充。
- 文字：玫瑰红系高对比文字。
- 光效：静态外发光与轻微内光，不播放动画。

### 4.3 Premium

- 边框：白金为主、带细微冷暖色变化的流动渐变边框。
- 背景：黑曜石般的近黑渐变，确保与页面亮暗主题均形成稳定高级感。
- 文字：多色渐变流光，保留可读的基础亮度，并添加文字光晕。
- 光效：外层彩色柔光，不扩大组件几何尺寸、不影响布局计算。
- 动画：仅改变渐变位置或角度，避免动画宽高、边距等布局属性。
- reduced-motion：停止所有流动，只保留静态渐变与光效。

## 5. 组件行为契约

| 输入 | 匹配结果 | 输出 |
| --- | --- | --- |
| `vip`、`VIP`、`Vip` | VIP | VIP 专属铭牌，显示原始输入文本 |
| `svip` 的任意大小写组合 | SVIP | SVIP 专属铭牌，显示原始输入文本 |
| `premium` 的任意大小写组合 | Premium | Premium 专属铭牌，显示原始输入文本 |
| `default` | 普通身份 | 普通文本 `default` |
| 其他非空字符串 | 普通身份 | 原样普通文本 |
| `null`、`undefined`、仅空白 | 空身份 | 不渲染内容 |

- 用于匹配时执行 `trim().toLowerCase()`。
- 专属铭牌展示去除首尾空白并自动大写的身份文本；普通身份保留原始非空输入，不自动翻译、不增加图标或前缀。
- 本次不导出身份枚举，不限制后端未来返回其他分组字符串。

## 7. 开发者手动验证建议

1. 使用 `vip`、`VIP`、`Vip`、`svip`、`premium` 检查铭牌样式和原始文本保留。
2. 使用 `default`、空值和任意未知分组，确认不应用专属铭牌样式且原有展示语义不变。
3. 在亮色和暗色主题下检查边框、背景、文字对比度及光晕是否影响相邻内容。
4. 在桌面和移动端检查个人资料头部不出现横向溢出，用户名、角色、用户 ID、邮箱和用户组信息均可见。
5. 启用系统 `prefers-reduced-motion: reduce`，确认 Premium 停止边框和文字流动，但保留静态高级效果。
6. 由开发者自行运行项目需要的测试、类型检查、Lint 和构建命令，并记录结果。

AI 未执行上述验证。

## 8. 风险、回滚与兼容性

- 风险：Premium 多层渐变与光晕在不同浏览器的颜色表现略有差异；使用标准渐变、遮罩和静态降级，避免依赖实验性脚本能力。
- 风险：个人资料信息行空间有限；保持紧凑尺寸、单行与收缩规则，不把铭牌移动到姓名徽章行。
- 风险：过强光晕可能影响邻近邮箱文本；实现时限制阴影扩散和不透明度，并在亮暗主题下检查。
- 兼容性：仅前端展示变更，不涉及 API、数据库、权限、i18n locale 或后端容器。
- 回滚：恢复 ProfileHeader 的普通文本节点，删除公共组件和对应局部 CSS 即可；不会产生数据迁移或配置残留。
